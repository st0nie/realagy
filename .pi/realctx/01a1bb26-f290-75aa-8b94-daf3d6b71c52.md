`fullMcpOutput` defaults to true. `src/acp/driver.ts` derives a private agy under `~/.pi/agent/realagy/derived-bin/` and launches it by absolute path; it never modifies the source or `PATH`. `src/acp/output-patch.ts` and `binary-image.ts` support Windows x64 PE, Linux x64 ELF, and macOS arm64 Mach-O, require one unique architecture-specific decorator signature, preserve the original branch target, use SHA-256-keyed atomic cache entries plus a derivative hash sidecar, and ad-hoc sign macOS derivatives via shared `signMacOSBinary`. Unknown versions/architectures fail closed; `fullMcpOutput: false` selects original agy. Live agy 1.5.3 ACP/custom-agent probes verified complete large single and ordered batch MCP outputs; `npm run check` passed with 172 tests.

Official agy binaries for offline patch verification use manifest `https://antigravity-cli-auto-updater-974169037036.us-central1.run.app/manifests/<platform>.json`, with platform names `darwin_arm64`, `windows_amd64`, `linux_amd64` (underscore form; `darwin-arm64` returns 404). Each manifest gives `url` and `sha512`. For 1.5.3, paths are `.../antigravity-cli/1.5.3-6604829099950080/{darwin-arm/cli_mac_arm64.tar.gz,windows-x64/cli_windows_x64.exe,linux-x64/cli_linux_x64.tar.gz}`. `llvm-objdump` on this machine disassembles arm64 Mach-O.

For macOS arm64 ACP prompt admission in 1.5.3 (VA `0x102a68de4`), `cbnz x1,L1; cbnz x4,L1+4; <-32602 "Empty prompt">; L1: cbz x4,L3; ldr x6,[sp,#0xe8]; cbz x6,L3+4; <"Images can't answer" check>; L3: ldr x6,[sp,#0xe8]; L4 body`. `src/acp/continuation-patch.ts` `patchArm64` mirrors the x64 adapter: second `cbnz` becomes `b L1`, L1 becomes NOP, and the third `cbz` on register x6 becomes x4. Matching is structural (wildcard registers/displacements/slot), unique, and requires `movn -32602` in the error block. Verified statically against the official binary; Windows x64 PE also matches the x64 adapter. The derived Mach-O is ad-hoc signed; the patch was not executed on a Mac.
