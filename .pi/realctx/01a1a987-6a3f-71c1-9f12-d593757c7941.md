realagy (2026-11): provider plans each user turn via src/transcript.ts planTurn(): reuses warm ACP session (AcpSessions.warm set only after a clean OK turn: sessionId, cwd, message count, sha256 fingerprint excluding thinking, system prompt, tool names) and sends only the delta (plain user text, or `pi://transcript-delta` resource); otherwise fresh session with full `pi://transcript`. DriverTurnRequest.fallback carries the full input; AcpDriver uses it when session/load fails. Driver tracks #liveSessions per server process (cleared on respawn). Usage: driver emits `step_usage` activities from agy SQLite steps (step_type 15, metadata field 9) at each bridge_call and at prompt end; provider syncUsage puts exact per-call input/cacheRead/output into pi Usage and latest-call context into totalTokens; occupancy from usage_update is fallback; unmeasured => zero usage (pi estimates). usageEstimate default is now 'off'. UsageMeter (src/quota.ts) drives footer status key 'realagy-usage' and `/realagy usage` (agy CLI `--print /usage` if on PATH/AGY_CLI_BIN). REALAGY_TRACE_USAGE=1 logs to ~/.pi/agent/realagy/usage-trace.jsonl. Fake ACP server supports FAKE_ACP_DB_DIR and session/load of id 'missing' errors.

`agy acp` concatenates `session/prompt` blocks (`Content of pi://transcript:\n...` + `prompt`) into a single `USER_INPUT` step and truncates it from the front at 192,000 UTF-8 bytes (`<truncated N bytes>`), which cuts off the newest messages and current user prompt when `pi://transcript` grows large.

How `realagy` (`src/transcript.ts`, `src/provider.ts`) handles this and coexists with `realctx` and `pi-lens`:
1. `serializeBounded` caps `pi://transcript` and `pi://transcript-delta` bodies at `MAX_TRANSCRIPT_BYTES` (160,000 UTF-8 bytes): it keeps `<pi-system>`, any leading `<realctx-history>` summary blocks, and the newest suffix of messages intact while collapsing older middle messages into `<pi-transcript-omitted messages="N">` and renumbering attached images sequentially.
2. `serializeMessage` applies `stripForgedRealctx` (matching `realctx` §9.2 `stripForged`) to assistant text blocks, and `persistentMessages` ignores transient one-request `[pi-lens automated (check|context) — not a user request]` messages when computing `warmAfterTurn` and `planTurn` fingerprints so neither `realctx` post-turn hygiene cleanup nor `pi-lens` ephemeral diagnostic injections invalidate warm ACP sessions.
3. `createStreamSimple` tracks `sessions.turnPrefix` (`prefixSnapshot(context.messages)`) across tool re-entries; if `realctx` compacts or drops earlier messages mid-turn during a tool loop, `prefixIntact` fails and `onCompleted` leaves `sessions.warm = undefined` so the next user turn opens a fresh ACP session with the compacted transcript.
