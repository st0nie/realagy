realagy (2026-11): provider plans each user turn via src/transcript.ts planTurn(): reuses warm ACP session (AcpSessions.warm set only after a clean OK turn: sessionId, cwd, message count, sha256 fingerprint excluding thinking, system prompt, tool names) and sends only the delta (plain user text, or `pi://transcript-delta` resource); otherwise fresh session with full `pi://transcript`. DriverTurnRequest.fallback carries the full input; AcpDriver uses it when session/load fails. Driver tracks #liveSessions per server process (cleared on respawn). Usage: driver emits `step_usage` activities from agy SQLite steps (step_type 15, metadata field 9) at each bridge_call and at prompt end; provider syncUsage puts exact per-call input/cacheRead/output into pi Usage and latest-call context into totalTokens; occupancy from usage_update is fallback; unmeasured => zero usage (pi estimates). usageEstimate default is now 'off'. UsageMeter (src/quota.ts) drives footer status key 'realagy-usage' and `/realagy usage` (agy CLI `--print /usage` if on PATH/AGY_CLI_BIN). REALAGY_TRACE_USAGE=1 logs to ~/.pi/agent/realagy/usage-trace.jsonl. Fake ACP server supports FAKE_ACP_DB_DIR and session/load of id 'missing' errors.

`agy acp` concatenates `session/prompt` blocks (`Content of pi://transcript:\n...` + `prompt`) into a single `USER_INPUT` step and truncates it from the front at 192,000 UTF-8 bytes (`<truncated N bytes>`), which cuts off the newest messages and current user prompt when `pi://transcript` grows large.

How `realagy` (`src/transcript.ts`, `src/provider.ts`) handles this and coexists with `realctx` and `pi-lens`:
1. `serializeBounded` caps `pi://transcript` and `pi://transcript-delta` bodies at `MAX_TRANSCRIPT_BYTES` (160,000 UTF-8 bytes): it keeps `<pi-system>`, any leading `<realctx-history>` summary blocks, and the newest suffix of messages intact while collapsing older middle messages into `<pi-transcript-omitted messages="N">` and renumbering attached images sequentially.
2. `serializeMessage` applies `stripForgedRealctx` (matching `realctx` §9.2 `stripForged`) to assistant text blocks, and `persistentMessages` ignores transient one-request `[pi-lens automated (check|context) — not a user request]` messages when computing `warmAfterTurn` and `planTurn` fingerprints so neither `realctx` post-turn hygiene cleanup nor `pi-lens` ephemeral diagnostic injections invalidate warm ACP sessions.
3. `createStreamSimple` tracks `sessions.turnPrefix` (`prefixSnapshot(context.messages)`) across tool re-entries; if `realctx` compacts or drops earlier messages mid-turn during a tool loop, `prefixIntact` fails and `onCompleted` leaves `sessions.warm = undefined` so the next user turn opens a fresh ACP session with the compacted transcript.

`realagy` maintains 1-to-1 warm ACP session continuity across `/reload`, `pi -c` / `/resume`, `/tree` branch switches, `/tree` branch rewinds to earlier turns, and all `realctx` / `pi-lens` transformations:

1. **Persisted `WarmSession` checkpoints (`realagy-warm-session`)**:
   - At turn completion, `AcpDriver` records `maxStepIdx` (`lastStepIdx(turn.dbPath)` in `~/.gemini/antigravity-cli/conversations/<sessionId>.db`) on `TurnOutcome`.
   - `warmAfterTurn` (`src/transcript.ts`) records `sessionId`, `cwd`, `count`, `hash`, `keys` (`nonHistoryKeys`), `maxStepIdx`, `systemPrompt`, and `tools`.
   - `extensions/index.ts` appends `{ customType: "realagy-warm-session", data: warm }` via `pi.appendEntry` on `turn_end` and restores `{ warm, checkpoints }` via `restoreWarmSessions(branchEntries, allEntries)` on `session_start` and `session_tree` (including off-branch custom entries when `/tree` selects an assistant message node before its trailing custom entries).

2. **`/tree` branch rewind via SQLite step-boundary forking (`src/acp/step-usage.ts`)**:
   - `selectTurnPlan` (`src/provider.ts`) evaluates candidate checkpoints and picks the warm match with the smallest `deltaMessages` (longest matched prefix).
   - `resolveSessionAtStep` checks `lastStepIdx(dbPath)` against `warm.maxStepIdx`. When a `/tree` rewind selects an earlier turn whose `<sessionId>.db` has already advanced past `maxStepIdx`, `forkConversationAtStep` copies `<sessionId>.db` to `<forkedSessionId>.db`, deletes `steps` (`idx > maxStepIdx`), prunes `gen_metadata` (field 2 packed step indices `> maxStepIdx`) and `executor_metadata` (field 3 end step `> maxStepIdx`), and updates `trajectory_meta` and `trajectory_metadata_blob` with `forkedSessionId`. `agy acp` loads `<forkedSessionId>.db` via `session/load` at that exact historical turn while leaving the other branch's store untouched.

3. **Full `realctx` & `pi-lens` invariance (`src/transcript.ts`)**:
   - `messageKey` keys `toolResult` by identity (`["toolResult", toolName, toolCallId, Boolean(isError)]`), normalizes `user` messages by stripping `realctx` placeholders/path-notes and preserving `hasImage` across `[#N dropped · user image ...]` replacements, and strips forged `realctx` tags from `assistant` text.
   - `splitWarmTranscript` (used by both `planTurn` and mid-turn `prefixIntact`) matches the suffix of `warm.keys` after any leading `<realctx-history>` chunks so `realctx` historian compression (between turns or mid-turn during tool loops) never invalidates warm ACP session reuse.

`realagy` warm ACP session continuity (`src/transcript.ts`, `src/provider.ts`, `extensions/index.ts`) works with arbitrary Pi `context` extensions without per-extension regex workarounds:
1. Tool-call reentries (`deps.driver.reentry()` in `src/provider.ts`) do not discard the turn when request #1 had active-prompt `context` hook decorations that are absent on tool-result continuations; `onCompleted` always builds `warmAfterTurn(context, final, ...)` from the turn's final transcript state.
2. `WarmSession.items` (`WarmItem[]` in `src/transcript.ts`) records `{ role, key, userText }` for each non-system, non-summary message:
   - `toolResult` is keyed by structural identity (`["toolResult", toolName, toolCallId, Boolean(isError)]`).
   - `user` is keyed by `primaryUserText` (the first non-ephemeral `{ type: "text" }` block, ignoring dropped historical images and extra extension-appended `{ type: "text" }` blocks), and `userTextsMatch` matches line-bounded headers/trailers (`startsWith("${shorter}\n")`, `endsWith("\n${shorter}")`, `includes("\n${shorter}\n")`) added only while a prompt is active.
   - `matchSequence` skips unpersisted transient `user` messages injected alongside a turn's real `user` message once that turn moves into history.
   - `matchWarmItems` matches an intact suffix of recent turns (`drop >= 2`, `kept >= 2`, starting at a `user` turn boundary) when any context manager compresses or drops older turns into strictly fewer leading `user` summary messages (`0 <= lead < drop`), while rejecting manual Pi `/compact` (`COMPACTION_SUMMARY_HEADER` / `pi.on("session_compact")`) and in-place edits (`lead === drop`) as fresh sessions.
