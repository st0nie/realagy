realagy (2026-11; checkpoint/tool changes since 2026-11-06).

**Turn planning** (`src/transcript.ts` `planTurn()`): reuses a warm ACP session and sends only the delta (plain user text, or a `pi://transcript-delta` resource). Otherwise it opens a fresh session with the full `pi://transcript`.
- The warm fingerprint covers sessionId, cwd, message count, a sha256 that excludes thinking, and the system prompt.
- `matchWarm` no longer rejects when `warm.tools !== index.tools()`. Instead, `planFromMatch` adds `<pi-tools-update>` (active tool names) to a `pi://transcript-delta`.
- `DriverTurnRequest.fallback` carries the full input. AcpDriver uses it when session/load fails.
- The driver tracks `#liveSessions` per server process (cleared on respawn).

**Usage**:
- The driver emits `step_usage` activities from agy SQLite steps (step_type 15, metadata field 9) at each bridge_call and at prompt end.
- Provider `syncUsage` puts exact per-call input/cacheRead/output into pi Usage and the latest-call context into totalTokens.
- Occupancy from usage_update is a fallback. Unmeasured means zero usage (pi estimates). The usageEstimate default is 'off'.
- UsageMeter (`src/quota.ts`) drives footer status key 'realagy-usage' and `/realagy usage` (agy CLI `--print /usage` if on PATH/AGY_CLI_BIN).
- `REALAGY_TRACE_USAGE=1` logs to `~/.pi/agent/realagy/usage-trace.jsonl`.

**Tool bridging**:
- pi-bridge lists every model-facing pi tool (`exposure` direct/model-only, active or not) plus any active tool (`bridgedPiTools` in `src/bridge-catalog.ts`).
- The tool policy names the same list, so it stays stable and cache-friendly.
- `dispatchablePiTool` runs only currently active tools. Others get "Pi tool X is not active in pi right now. Active pi tools: …".

**Checkpoints** (`src/provider.ts`):
- `recordStep` runs at each `bridge_call` (the driver adds `sessionId` + `maxStepIdx`). It is memory-only in `sessions.step` and replaced by the turn's next checkpoint.
- `recordWarm` runs on completed turns AND on aborted turns with `outcome.promptDelivered` (driver: final prompt sent + `userInputSince(dbPath, promptCursor)`; step_type 14).
- Only settled checkpoints call `onWarm` (persisted at `turn_end`), to avoid O(steps×transcript) session-file growth.
- At turn end, `AcpDriver` records `maxStepIdx` (`lastStepIdx(turn.dbPath)` in `~/.gemini/antigravity-cli/conversations/<sessionId>.db`) on `TurnOutcome`.
- `warmAfterTurn` records `sessionId`, `cwd`, `count`, `hash`, `keys` (`nonHistoryKeys`), `items`, `maxStepIdx`, `systemPrompt`, and `tools`.
- `extensions/index.ts` appends `{ customType: "realagy-warm-session", data: warm }` via `pi.appendEntry` on `turn_end`.
- It restores `{ warm, checkpoints }` via `restoreWarmSessions(branchEntries, allEntries)` on `session_start`/`session_tree`, including off-branch custom entries when `/tree` selects an assistant node before its trailing custom entries.

**Esc**:
- `streamSimple` called with an already-aborted signal finishes "aborted" without planning (`void cancelActive`).
- `failParkedCalls(roundTrips, outcome)` also fails escalated calls on aborted turns.
- Orphaned parked turns record their checkpoint when cancelled.

**/tree**:
- The extension captures active tools on `session_before_tree`.
- On `session_tree` it deactivates `treeRestoreExtras()` (`src/tool-loadout.ts`: tools active now, inactive before, and never declared in branch system messages). This undoes pi's `_restoreToolsFromTranscript()` activation of situational tools such as pi-lens's.

**/tree rewind fork** (`src/acp/step-usage.ts`):
- `selectTurnPlan` picks the warm match with the smallest `deltaMessages`.
- `resolveSessionAtStep` compares `lastStepIdx(dbPath)` with `warm.maxStepIdx`. If the db has advanced past it, `forkConversationAtStep` does the following:
  - copies `<sessionId>.db` to `<forkedSessionId>.db`;
  - deletes `steps` with `idx > maxStepIdx`;
  - prunes `gen_metadata` (field 2 packed step indices > maxStepIdx) and `executor_metadata` (field 3 end step > maxStepIdx);
  - updates `trajectory_meta`/`trajectory_metadata_blob`.
- `agy acp` then loads the fork via `session/load`.

**agy 192,000-byte truncation**: `agy acp` concatenates prompt blocks into one `USER_INPUT` step and front-truncates at 192,000 UTF-8 bytes (`<truncated N bytes>`). `serializeBounded` handles this:
- It caps `pi://transcript`/`pi://transcript-delta` at `MAX_TRANSCRIPT_BYTES` (160,000).
- It keeps `<pi-system>`, leading `‹realctx-history>` blocks, and the newest messages.
- It collapses the middle into `<pi-transcript-omitted messages="N">` and renumbers images.

**realctx/pi-lens/context-extension invariance**:
- `serializeMessage` applies `stripForgedRealctx` to assistant text.
- `persistentMessages` ignores `[pi-lens automated (check|context) — not a user request]` messages.
- `createStreamSimple` tracks `sessions.turnPrefix` (`prefixSnapshot`). If `prefixIntact` fails mid-turn, `sessions.warm = undefined`.
- `messageKey` keys toolResult by `["toolResult", toolName, toolCallId, Boolean(isError)]` and strips realctx placeholders/path-notes from user messages (preserving `hasImage`).
- `splitWarmTranscript` matches `warm.keys` after leading `‹realctx-history>` chunks.
- Reentries (`deps.driver.reentry()`) do not discard the turn. `onCompleted` builds `warmAfterTurn` from the final transcript.
- `WarmItem` `{ role, key, userText }`: a user message is keyed by `primaryUserText`.
  - `userTextsMatch` accepts line-bounded headers/trailers.
  - `matchSequence` skips transient user messages.
- `matchWarmItems` accepts an intact recent suffix (`drop >= 2`, `kept >= 2`, at a user boundary, `0 <= lead < drop`). It rejects Pi `/compact` (`COMPACTION_SUMMARY_HEADER` / `session_compact`) and `lead === drop`.
