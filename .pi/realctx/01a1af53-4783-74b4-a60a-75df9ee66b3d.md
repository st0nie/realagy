`agy acp` (verified in binary v1.5.1 `mcpcore.(*McpClientSessionInstance).callToolRaw` and `acp.buildMCPServerSpec`) enforces a hardcoded 180-second (`0x29e8d60800` ns) `context.WithTimeout` on every MCP `tools/call` request, because `buildMCPServerSpec` does not populate `MCPServerConfig.Timeout`.

In `realagy` (`src/provider.ts`):
- `ESCALATE_AFTER_MS` is 150,000 ms (2.5 minutes), staying safely under `agy`'s 180s MCP timeout while covering `realtasks`'s default 120s foreground `bash` window without premature escalation.
- Once a tool call escalates at 150s, its initial HTTP abort signal is detached and its hard timer is cleared (no 30-minute kill on running tools; `ESCALATED_TTL_MS` only prunes settled results in `#polls`).
- `bridge_poll_result` (`ToolRoundTrips.#poll`) long-polls for up to `ESCALATE_AFTER_MS` (150s) per call, waking immediately via `PollResult.waiters` when `resolve()` or `#fail()` settles the tool call, or returning `STILL RUNNING` again after 150s.
- If `agy` stops polling and ends its `session/prompt` turn while an escalated pi tool is still running, `sessions.parked` records the warm checkpoint at the `toolUse` message when `handle.outcome` settles, and `matchWarm` in `src/transcript.ts` accepts deltas containing `toolResult` messages so the late tool output is delivered to the same warm ACP session via `pi://transcript-delta`.
