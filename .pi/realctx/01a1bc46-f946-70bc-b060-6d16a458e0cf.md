realctx can apply several `<realctx-history part="hN">` messages in one request (and append more later); Pi's effective context then starts with N consecutive summary user messages, but agy's native trajectory has ONE first user step. `src/acp/trajectory-sync.ts` merges leading summaries (`leadingSummaryCount`/`mergedSummaryItem`/`mapWarmItems`) joined with "\n\n" into native step 0; summary updates are only written when bytes change (re-sync is a no-op). Before this fix (commit after 23d9b2a), qbot failed with misleading "Native tool step 2 has no recorded result (status 7)" at HEAD and, after error-layout support, "History summary boundary is not unique (0 candidates)". Repro harness: /tmp/rs/repro.mts <session.jsonl> <db copy> <lastEntryIndex> rebuilds effective context from realctx history chunks in the session JSONL.
