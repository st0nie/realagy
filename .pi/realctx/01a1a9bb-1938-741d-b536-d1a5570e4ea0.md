User wants realagy minimal: the only slash command is `/agy usage` (with getArgumentCompletions); no /realagy commands. Nothing is shown in pi's footer status, and there is no background quota polling. Cache-hit rate and plan quota are displayed only when the user runs `/agy usage`, which calls `agy --print /usage --output-format json` (~5–10 s) at that moment (command.data.groups[].buckets[] with window, remaining_fraction, reset_time; groups 'Gemini Models', 'Claude and GPT models', 'Gemini 4 Argon'). UsageMeter in src/quota.ts only accumulates step usage and renders report(); there is no status()/groupForModel/onChange any more. Usage docs follow forgejo.wolf109909.top/webj8/webjet (webjet structure) and live only in README.md (docs table, install, commands, layout) plus docs/architecture.md and docs/development.md. AGENTS.md and CHANGELOG.md were removed; do not recreate them or a changelog.

`/agy usage` in `extensions/index.ts` stays responsive during quota queries via:
1. Interactive spinner & cancellation (no pre-fetch status): when `ctx.mode === "tui"`, `runWithLoader` mounts `BorderedLoader` via `ctx.ui.custom` (`Loading Antigravity plan quota…` / `Checking Antigravity CLI…`), wiring `loader.onAbort` (Esc) and `session_shutdown` to an `AbortSignal` passed into `fetchCliUsage(bin, { signal })`, and calls `ctx.ui.notify(finalReport, "info")` only once after the query settles so stale results never flash first.
2. Early stdout resolution on CLI fallback: `agy --print /usage --output-format json` flushes its single-line JSON output ~1.5 s before its internal language server finishes shutting down; `fetchCliUsage` in `src/quota.ts` parses `child.stdout` on newline and resolves as soon as `parseCliUsage` succeeds while letting `agy` exit cleanly on its own.

Caveat on /usage quota data for Gemini 4 Argon: measured 2026-11-05 (12:02-12:09), three 'Gemini 4 Argon (High)' prompts (two through pi+realagy over `agy acp`, one through plain `agy --model "Gemini 4 Argon (High)" -p`) all really ran on Argon (agy logs: "Switching model in session ... Gemini 4 Argon (High) (enum: MODEL_PLACEHOLDER_M417)" or print mode model="Gemini 4 Argon (High)"; each turn makes 2 streamGenerateContent calls, a fast title call plus the main call; ~10k input / ~4.8k output), yet `agy --print /usage --output-format json` never showed the Argon weekly bucket drop. Repeated idle polls alternate between two stale server snapshots (Argon remaining_fraction 0.98920 vs 0.98859; Gemini Models weekly 0.63541 vs 0.63611, 5h 0.79356 vs 0.79067), so per-prompt deltas cannot be measured from /usage. This happens with plain agy too, so it is server-side quota accounting/caching, not a realagy bug. Helper: poll /usage several times and compare.

`/agy usage` (`extensions/index.ts`, `src/quota.ts`) shows only `BorderedLoader("Loading Antigravity plan quota…")` while fetching and calls `ctx.ui.notify` once after `fetchCliUsage` resolves (no pre-fetch `ctx.ui.notify` call, preventing stale-quota flicker). `UsageMeter.report()` formats each quota group header as `<name> · <models>` (stripping `Models within this group:`), orders `Current session (5h)` before `This week`, renders a 25-char `━`/`─` usage bar with right-aligned `<X>% used` (rounded up to `0.1%` so any non-zero usage never reads `0% used`), and prints `Starts with your first message` (unused 5h), `Quota available` (other unused), `Quota exhausted`, or `Resets <today|tomorrow|Weekday> HH:MM (in Xd Yh|Xh Ym|Xm)`.
