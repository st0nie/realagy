Verified live 2026-11 (cancel persistence on 2026-11-06, gemini-3.8-flash, AcpDriver probe) against `agy acp` 1.5.1 (probe scripts in /tmp/agyprobe):
- `session/cancel` sent as a JSON-RPC NOTIFICATION (no id, ACP spec) makes the in-flight `session/prompt` resolve immediately with `stopReason: "cancelled"`. The same session and process stay usable for the next prompt.
- Sent as a REQUEST (with id), the prompt is also cancelled, but the cancel request itself is NEVER answered, so awaiting it hangs until timeout.
- A cancelled prompt still stores its USER_INPUT step. Even when cancelled ~50 ms after sending, before any model output, `<conversationsDir>/<sessionId>.db` already holds it (`step_type` 14, status 3). Its payload starts with the prompt text (e.g. `Content of pi://transcript:`).
- Cancelling mid-stream also leaves the partial PLANNER_RESPONSE step (15).
- A follow-up prompt on the same session recalled facts from the cancelled prompt (secret word + topic).
- So "a user-input step after the turn's starting step cursor" is reliable evidence that a cancelled turn's prompt reached the session. This is used for warm checkpoints of aborted turns.
- `session/load` with an unknown sessionId (even a random UUID) SUCCEEDS and returns an empty session with that id. It never errors, so "load failed → fresh session" fallbacks never trigger. Check that `<conversationsDir>/<id>.db` exists instead.
- initialize advertises `agentCapabilities.sessionCapabilities = { resume, close, load, list, additionalDirectories }`.
- `session/resume {sessionId, cwd, mcpServers}`:
  - restores history WITHOUT replaying it as session/update notifications;
  - keeps model memory (verified with a secret-word test across processes);
  - errors -32603 "Failed to read session ..." for unknown ids.
- `agy acp` exits ~100 ms after its stdin closes, so it does not outlive a dead parent.
- PromptResponse.usage fields are camelCase: inputTokens, outputTokens, cachedReadTokens, cachedWriteTokens, thoughtTokens, totalTokens.
- Conversation stores `~/.gemini/antigravity-cli/conversations/<id>.db` are SQLite in WAL mode with lingering -wal/-shm files. Copying only the .db file loses uncheckpointed steps; use `VACUUM INTO` instead.
