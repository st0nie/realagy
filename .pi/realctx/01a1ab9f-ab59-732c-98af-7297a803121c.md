Verified live 2026-11 against `agy acp` 1.5.1 (probe scripts in /tmp/agyprobe):
- `session/cancel` sent as a JSON-RPC NOTIFICATION (no id, ACP spec) makes the in-flight `session/prompt` resolve immediately with `stopReason: "cancelled"`; the same session and process stay usable for the next prompt.
- Sent as a REQUEST (with id), the prompt is also cancelled but the cancel request itself is NEVER answered (so awaiting it hangs until timeout).
- `session/load` with an unknown sessionId (even a random UUID) SUCCEEDS and returns an empty session with that id — it never errors, so "load failed → fresh session" fallbacks never trigger. Check `<conversationsDir>/<id>.db` exists instead.
- initialize advertises `agentCapabilities.sessionCapabilities = { resume, close, load, list, additionalDirectories }`. `session/resume {sessionId, cwd, mcpServers}` restores history WITHOUT replaying it as session/update notifications, keeps model memory (verified with a secret-word test across processes), and errors -32603 "Failed to read session ..." for unknown ids.
- `agy acp` exits ~100 ms after its stdin closes (so it does not outlive a dead parent).
- PromptResponse.usage fields are camelCase: inputTokens, outputTokens, cachedReadTokens, cachedWriteTokens, thoughtTokens, totalTokens.
- Conversation stores `~/.gemini/antigravity-cli/conversations/<id>.db` are SQLite in WAL mode with lingering -wal/-shm files; copying only the .db file loses uncheckpointed steps (use `VACUUM INTO`).
