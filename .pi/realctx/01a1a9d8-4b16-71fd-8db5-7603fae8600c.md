Verified 2026-11-05 with `agy acp` 1.5.0 (agy transcripts at ~/.gemini/antigravity-cli/brain/<sessionId>/.system_generated/logs/transcript.jsonl, steps/<n>/output.txt):
- Session/new `_meta.antigravity.enabledTools` (and `disabledTools`) is ignored, so realagy no longer tries to restrict agy's tools; it sends only `eagerMcpServers: ["pi-bridge"]`. agy's native tools stay available: read_file, run_command, edit_file, write_file, search_web, subagents, etc. (no `view_file`; images are viewed with native `read_file`). realagy runs turns with skipPermissions=true (ACP mode "yolo") and auto-approves agy permission requests (AcpConnection#answerPermission), so native run_command/read_file/write_file run outside pi's permissions; models do use them.
- src/image-results.ts and the pi-images-* staging dir were removed per the user's decision (commit d008ad5). pi image results now go back as plain MCP image blocks, which agy 1.5.0 offloads to brain/<session>/.system_generated/steps/<n>/media_*.png AND shows the model in the same turn (verified live: a pi `read` of a PNG was described correctly, no extra tool call).
- agy refuses native read_file inside ~/.gemini ("permission check failed for read_file", even in yolo), so never hand the model files there.
- Fresh-session transcript images still go as ACP prompt image blocks (stored as brain/<sessionId>/.user_uploaded/uploaded_media_<ts>.png); log line "Sending user message ... media=1".
- CLI permissions live in ~/.gemini/antigravity-cli/settings.json `permissions.{allow,deny,ask}` with action(target) rules (read_file, write_file, command, mcp, read_url, execute_url, unsandboxed).
