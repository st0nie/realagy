Verified live 2026-11-06 with `agy acp` 1.5.1 (probe /tmp/agyprobe/pitools.mts):
- initialize advertises `agentCapabilities._meta.antigravity.systemPrompt = { append: true }`. Passing `session/new` `_meta.antigravity.systemPrompt: { append: "<text>" }` appends to agy's system prompt; Gemini 3.8 Flash, Claude Sonnet 5.5 and GPT-OSS 120B all followed it (marker test). A tool-policy text there made all three use pi-bridge `bash`/`write`/`read` instead of native tools with no user-prompt changes. realagy uses only `eagerMcpServers: ["pi-bridge"]` plus this append.
- `_meta.antigravity.disabledTools` / `enabledTools` are still ignored in 1.5.1 (native run_command ran). agy's native tools stay available: read_file, run_command, edit_file, write_file, search_web, subagents, etc. (no `view_file`; images are viewed with native `read_file`).
- Session modes are only `default`, `accept-edits`, `plan` (session/new `modes.availableModes`; config options `model`, `thought_level`, `mode`). `yolo`/`auto_edit` fail with -32602 "Unknown mode".
- In mode `default`, native `run_command` / file edits send `session/request_permission` (options allow_once, reject_once; toolCall has `name`, `kind` e.g. `execute`), which realagy auto-approves (AcpConnection#answerPermission). pi-bridge MCP tool calls, native reads (`read_file`) and `invoke_subagent` send NO permission request. Refusing a native command WITHOUT a policy in the prompt makes the model give up with an empty reply.
- `invoke_subagent` returns immediately and the subagent runs as a separate background conversation (brain/<subagentId>/); its own `run_command` sent no permission request to the ACP client and stalled. Subagents can only be discouraged via the system prompt.
- Native `run_command` backgrounds a command after `WaitMsBeforeAsync` (model chose 500 ms). The model ends the prompt (`stopReason: end_turn`) while the tool_call is still `in_progress`. On completion agy writes `brain/<sessionId>/.system_generated/messages/<uuid>.json` (sender `<sessionId>/task-N`, content with exit code + output, `sourceMetadata.tool.toolCall.id` = ACP toolCallId), marks it in `messages/read.json`, injects a SYSTEM_MESSAGE step and runs an AUTONOMOUS agent turn (SYSTEM_MESSAGE + PLANNER_RESPONSE in transcript.jsonl). Live task output streams to `.system_generated/tasks/task-N.log`.
- ACP sends NOTHING while no prompt is in flight. Buffered frames (`tool_call_update status:completed` with rawOutput, then the autonomous turn's `agent_message_chunk`s) flush at the START of the next `session/prompt`, BEFORE the `user_message_chunk` echo. Unhandled, realagy's driver renders that backlog as part of the new pi reply.
- Transcripts at ~/.gemini/antigravity-cli/brain/<sessionId>/.system_generated/logs/transcript.jsonl, steps/<n>/output.txt.
- src/image-results.ts and the pi-images-* staging dir were removed per the user's decision (commit d008ad5). pi `read` results go back as plain MCP image blocks, which agy offloads to brain/<session>/.system_generated/steps/<n>/media_*.png AND shows the model in the same turn (verified live: a pi `read` of a PNG was described correctly, no extra tool call). This works for Gemini and Claude (both read text in a PNG); `gpt-oss-120b` is text-only and cannot see images even with native read_file, so realagy's catalog should not mark gpt-oss as image-capable.
- agy refuses native read_file inside ~/.gemini ("permission check failed for read_file"), so never hand the model files there.
- Fresh-session transcript images still go as ACP prompt image blocks (stored as brain/<sessionId>/.user_uploaded/uploaded_media_<ts>.png); log line "Sending user message ... media=1".
- CLI permissions live in ~/.gemini/antigravity-cli/settings.json `permissions.{allow,deny,ask}` with action(target) rules (read_file, write_file, command, mcp, read_url, execute_url, unsandboxed).
