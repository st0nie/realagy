Verified 2026-11-05 with `agy acp` 1.5.0 (agy transcripts at ~/.gemini/antigravity-cli/brain/<sessionId>/.system_generated/logs/transcript.jsonl, steps/<n>/output.txt):
- session/new `_meta.antigravity.enabledTools` is ignored: with ["view_file"], none, or ["read_file"] the model lists the same native tools: ask_question, define_subagent, edit_file, invoke_subagent, manage_subagents, manage_task, read_file, run_command, schedule, search_web, send_message, write_file (no `view_file`; images are viewed with native `read_file`). Because realagy runs turns with skipPermissions=true (ACP mode "yolo", auto-allow in AcpConnection#answerPermission), native run_command/read_file/write_file run outside pi's permissions; models do use them.
- Native read_file on realagy's staged image `~/.gemini/antigravity-cli/pi-images-*/<sha>.png` fails: "permission check failed for read_file" (agy protects its own data dir even in yolo). The model then read the original /tmp file with native read_file instead.
- ACP prompt image blocks (fresh-session transcript replay) work: agy stores them as brain/<sessionId>/.user_uploaded/uploaded_media_<ts>.png and the model sees them (log line "Sending user message ... media=1").
- CLI permissions live in ~/.gemini/antigravity-cli/settings.json `permissions.{allow,deny,ask}` with action(target) rules (read_file, write_file, command, mcp, read_url, execute_url, unsandboxed).
