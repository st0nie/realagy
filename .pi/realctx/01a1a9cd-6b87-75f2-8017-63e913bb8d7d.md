pi's footer shows `CH` from the LATEST assistant message only (cacheRead / (input+cacheRead+cacheWrite)) and hides it when that message has zero prompt tokens (footer.js getSessionStats). With agy, one model call that requests several tools becomes several pi toolUse messages (agy sends the MCP calls one after another, each after the previous result), and only the first gets the step's usage. realagy fixes this in src/acp/driver.ts pushExternal: when a bridge_call finds no new step in the conversation DB, it emits `siblingUsage(lastStep)` (src/acp/step-usage.ts): 100 prompt tokens split by the call's cache ratio, output 0, same contextTokens, steps 0. UsageMeter ignores steps === 0. REALAGY_TRACE_USAGE logs `bridge-call` events for diagnosing this.
