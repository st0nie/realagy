When a live realagy sync probe (e.g. `/tmp/rs/live2.mts repeat`) gets a stale-looking answer, inspect the conversation DB (`~/.gemini/antigravity-cli/conversations/<sid>.db`) before suspecting sync: `gen_metadata` rows hold the exact last request agy sent, so grep it for the old/new values to see if the stale token was in the input or only in the model's output. Pitfalls found: (1) pi's own retained assistant replies legitimately carry earlier values (even a hex suffix lets Gemini Flash reconstruct the full old value), so probe check-questions must not echo values (ask YES/NO); (2) after a summary the retained last assistant message still contains values; (3) `brain/<sid>/.system_generated/logs/transcript*.jsonl` are append-only logs that keep pre-sync values and are NOT model input; (4) agy injects a type-101 SYSTEM_MESSAGE step ("subagents … stopped due to server restart") on every restart/resume, which mapping tolerates.
