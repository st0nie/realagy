`src/models.ts` treats `-low`, `-medium`, `-high`, `-xhigh`, `-max` ACP slug suffixes as effort tiers of one pi model (`AGY_EFFORT_ORDER`, `TIER_RE`, `isAgyEffort`; `src/model-cache.ts` validates with `isAgyEffort`; `acpModelSlug` in `src/acp/driver.ts` knows the same suffixes).

pi-ai 1.5 `getSupportedThinkingLevels` offers low/medium/high unless `thinkingLevelMap[level] === null`, but offers `xhigh`/`max` ONLY when the map holds a non-null value. So `thinkingLevelMapFor` sets `xhigh: "xhigh"` / `max: "max"` exactly when the catalog lists that tier and leaves them unset otherwise. `toAgyEffort` resolves a missing level to the nearest listed tier, higher first.

Live catalog on agy 1.5.5 (2026-11): only `gemini-4-hydrogen` has an `-xhigh` tier (name suffix `(XHigh)`); no model has `-max`, so `-max` parsing is unverified against a real catalog. A live `xhigh` turn on `gemini-4-hydrogen` sent slug `gemini-4-hydrogen-xhigh` and completed. Before this change that slug was registered as a separate fixed-thinking pi model `gemini-4-hydrogen-xhigh`; that id no longer exists.

Probe scripts that import `@earendil-works/pi-ai` must live inside the repo directory (ESM resolution fails from /tmp).
