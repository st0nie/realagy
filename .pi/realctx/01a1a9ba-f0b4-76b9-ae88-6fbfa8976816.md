realagy does not download agy_acp_server.par and has no sign-in flow (src/acp/auth.ts and browser-capture.ts were removed). It spawns the user's Antigravity CLI as `agy acp` (default binArgs ["acp"] in acpServerArgs), resolved via AGY_BIN > PATH > ~/.local/bin/agy (src/acp/setup.ts resolveAgyBinary/ensureAgyReady, synchronous). If agy is missing, pi shows a notice with the official install script URL (antigravity.google/cli/install.sh); the user explicitly does not want auto-install. agy acp shares the CLI login and data dir ~/.gemini/antigravity-cli (GEMINI_HOME respected): conversations/<sessionId>.db for step usage, pi-images-* staging, settings.json queuedMessages. Verified live with agy 1.5.0: listModels and turns work without extra auth; PromptResponse.usage is returned (turn-cumulative).

realagy registers the `antigravity` provider via `pi.registerProvider(createProvider({...}))` (createProvider from @earendil-works/pi-ai) with `auth.apiKey = { name, resolve }` and no `login`, so pi never prompts for or stores a placeholder API key (the old legacy form needed `apiKey: "not-used"`). resolve returns `{ auth: {}, source: "agy CLI" }` when resolveAgyBinary() finds agy, else undefined. pi still lists every provider in /login (getLoginProviderOptions includes any provider with auth.apiKey or auth.oauth; at least one is required), but selecting it only shows "<name> is configured outside pi". Commands: `/agy setup` (install steps if agy missing, sign-in steps `agy` / `agy acp --login` if listModels fails, catalog reload when ready) and `/agy usage`. Verified: `pi -ne -e ./extensions --model antigravity/gemini-3-8-flash -p ...` works with no key.
