realagy no longer downloads agy_acp_server.par and has no sign-in flow (src/acp/auth.ts and browser-capture.ts were removed). It spawns the user's Antigravity CLI as `agy acp` (default binArgs ["acp"] in acpServerArgs), resolved via AGY_BIN > PATH > ~/.local/bin/agy (src/acp/setup.ts resolveAgyBinary/ensureAgyReady, synchronous). If agy is missing, pi shows a notice with the official install script URL (antigravity.google/cli/install.sh); the user explicitly does not want auto-install. agy acp shares the CLI login and data dir ~/.gemini/antigravity-cli (GEMINI_HOME respected): conversations/<sessionId>.db for step usage, pi-images-* staging, settings.json queuedMessages. Verified live with agy 1.5.0: listModels and turns work without extra auth; PromptResponse.usage is returned (turn-cumulative).
