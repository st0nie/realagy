Verified 2026-11-06 on agy 1.5.2 (Windows) by disassembly and live probes.

ACP: extractAntigravitySystemPrompt reads only `_meta.antigravity.systemPrompt.append`; other shapes are ignored. The agent name comes only from the server-wide flag `agy acp --agent NAME`, not from per-session meta; a file path is not accepted. Unknown names log `Agent "X" not found, falling back to default` in the ACP log file.

Discovery: global `~/.gemini/config/agents/NAME.md`; workspace `.agents/agents/NAME.md` or `.agents/agents/NAME/agent.md`; `--add-dir` folders (avoid: an added dir becomes the Command Working Directory). JSON agent files were never discovered; the global NAME/agent.md subfolder form was not found.

Leak into normal sessions: any discovered custom agent file (global or workspace) is offered to normal agy sessions as an invocable subagent. Its name and description go into the default agent's prompt data, and the model lists it in both `agy acp` and `agy -p`. Frontmatter `hidden: true` keeps it out of the default agent's prompt and subagent list, but `agy agents` still lists it. Apart from that, an agent file only changes the prompt and tools of processes started with `--agent NAME`; default sessions are otherwise unchanged.

Frontmatter keys: name, description, disabled, tools, excludeDefaultComponents, mainAgent, subagent, hidden, inheritCustomizations, inheritMcp, model, commandExecutionPolicy, mcpServers, skills, preloadSkills, plugins, rules, agents, hooks. The markdown body replaces the identity section. Extra headings add sections; they never replace built-in ones.

A default custom agent keeps built-in sections user_information, mcp_servers, user_rules, messaging, artifacts, guidelines, communication_style (artifacts and communication_style carry the file:// link rules). `excludeDefaultComponents: true` leaves exactly the body plus the ACP append. Native tools then shrink to manage_task, list_resources, read_resource: no run_command, read_file, edit_file, write_file or subagents.

MCP: servers provided over ACP stay connected, but their tools become lazy (call_mcp_tool plus a permission request); eagerMcpServers is ignored for custom agents. `tools:` accepts only registry tool names; MCP names there fail with "not found in registry". Working setup: `mcpServers` as a YAML list item `name: pi-bridge` with `tools: {bash: {eager: true}, read: {eager: true}}`, one entry per tool. No URL or token is needed, because it overlays the ACP server of the same name. Tools then show up as native `mcp_pi-bridge_TOOL` with no permission request. The map form and a "*" wildcard do not work.

Still working with such an agent: systemPrompt.append, model set_config_option, and session/resume in the same or a new process. Claude Sonnet 5.5 and GPT-OSS wrote plain paths. The real prompt text sits in the gen_metadata.data blob (latest idx) of `~/.gemini/antigravity-cli/conversations/ID.db`.
