Realagy's session database cleanup records only newly created agy ACP session IDs and the original database device/inode in `.realagy-session-ownership-v2.sqlite` beside `conversations/`. A successfully persisted replacement retires the old owned session; after seven days GC only removes the DB and SQLite WAL/SHM when all recorded Pi and ACP server PIDs are dead, identities are unchanged, and files have not been recently modified. A two-transaction deletion tombstone makes partial cleanup retryable and forces checkpoint replay instead of reopening a partial database. Resumption by a different realagy runtime marks a checkpoint shared and retains it indefinitely, because other Pi sessions can still reference it. Legacy/untracked and catalog-only sessions and all `brain/` files are never cleaned. Cleanup is triggered on session start after leasing the restored checkpoint and after replacements.
