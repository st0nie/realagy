Verified with Antigravity CLI 1.5.3: exact per-model-call usage lives in `~/.gemini/antigravity-cli/conversations/<sessionId>.db`, table `steps`, agent steps `step_type=15`, `metadata` protobuf field 9: varint 2=input, 3=output, 5=cache read. Field 4 (`cacheWrite`) is absent/0 for Gemini and Claude (`claude-opus-5-5`); Claude newly cached suffix tokens and Gemini uncached suffix tokens appear in field 2. Pi's native Anthropic provider instead records suffix tokens as `cacheWrite` (`W`), leaving `input` (`↑`) near 1–3 tokens/turn. `PromptResponse.usage` is turn-cumulative (`input_tokens`, `output_tokens`, `cache_read_tokens`). Historical check with `agy acp` 1.5.0 on 2026-11-05: two short Gemini 3.8 Flash turns (~8k prompt tokens) on a reused warm session both showed cacheRead=0.

Fresh sessions pay ~17.8k uncached input tokens on Gemini (~27.3k on Claude) on turn 1 before conversation history:
- `src/agent-profile.ts` marks all ~37–38 bridged `pi-bridge` tools `eager: true`, required because `agy` 1.5.2 ignores `eagerMcpServers` under custom agents with `excludeDefaultComponents: true`. Tool schemas create a static prefix of ~13,431 tokens on Gemini (~18k–20k on Claude), ~35.5 KB of tool JSON; largest schemas are `ask_user_question`, `replace_match`, `bash`, `realctx_recall`, `grep`.
- `freshInput` (`src/transcript.ts:392`) calls `getCurrentSystemPrompt(context.messages)`, rendering Pi's structured system message (~17 KB / ~4.4k+ tokens) into the `<pi-system>` header. This includes Pi's `sections.tools` (~2.5 KB of tool-snippet prose from `pi-coding-agent` `system-prompt.js`), duplicating descriptions in the MCP schemas and `toolPolicyPrompt` (`src/tool-policy.ts`).

Trimming constraints: `bridgedPiTools` (`src/bridge-catalog.ts`) and `matchWarm` (`src/transcript.ts`) keep all registered `direct`/`model-only` tools in a stable session catalog so mid-session activations (`pi-lens`, `/tree` restores) work via `pi-tools-update` deltas without respawning `agy` or busting prompt cache. `dispatchablePiTool` enforces active-only execution (`tests/bridge.test.ts`, `tests/extension-lifecycle.test.ts`). Trimming duplicate `sections.tools` prose via `getCurrentSystemMessage` sections, or inactive schemas, must preserve mid-session activation and cache stability.
