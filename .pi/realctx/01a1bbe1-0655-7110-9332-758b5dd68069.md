When Pi rewrites effective history while an `agy acp` turn is parked on `pi-bridge` tool calls, `src/provider.ts` resolves the pending Pi tool results, calls `driver.awaitBridgeResults()` (rejects with `agy did not record the pi tool results before synchronization` on timeout) BEFORE cancelling the turn, then sends `contextSync` with `discardCancelledTail: true`. Without the wait, agy is cancelled before persisting the result (native step stays status 6 `Executing` with no `140.2.1`, sync failed `Expected one protobuf field 1, found 0`).

`synchronizeConversation` (`src/acp/trajectory-sync.ts`) deletes trailing ASSISTANT/TOOL_RESULT steps after the last mapped step only when `discardCancelledTail` is set; between-turn sync never deletes them (fails "not represented"). Pi tools are never re-run. Steps are read with `SELECT *` + optional-column handling because older conversation DBs lack the `status` column.
