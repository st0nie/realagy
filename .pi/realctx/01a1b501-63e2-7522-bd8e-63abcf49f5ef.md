Static analysis of agy.exe 1.5.2 plus live ACP probe (2026-11-07):

**Mechanism**
- The main agent (cortex) auto-compacts long trajectories. It writes a `CORTEX_STEP_TYPE_CHECKPOINT` step (steps.step_type = 23 in `~/.gemini/antigravity-cli/conversations/<id>.db`).
- Later model calls see only "Steps up to STEP_N were compacted to fit the context window. Preserved below: the initial user request, the latest agent checkpoint summary, user messages, and a one-line log of the agent's actions. Tool outputs and agent reasoning from this range are omitted."
- The summary itself can be cut off ("The checkpoint summary has been truncated due to hitting max length").

**Config**
- `exa.cortex_pb.CheckpointConfig` lives inside CascadeConfig. Fields: enabled, token_threshold, context_window, max_user_requests, max_token_limit, strategy, checkpoint_model, checkpoint_prompt_override, etc.
- It is resolved per model by `config.resolveDefaultCheckpointConfig` / `utils.GetCheckpointConfigForModelInfo`.
- It is overridden by server experiments (`config.applyFeatureProviderCheckpointOverrideConfig`, keys `context-window/...` and `checkpoint-variant`).
- ACP has no way to set it.

**Reading the live config via ACP**
- Send `POST http://127.0.0.1:<port>/exa.language_server_pb.LanguageServerService/GetAvailableModels` with body `{}`. Get the port from the acp-server log; see `findAcpHttpPort` in `src/quota.ts`.
- Read `response.models.<id>.modelExperiments.experiments.CASCADE_USE_EXPERIMENT_CHECKPOINTER.stringValue`, which is JSON.

Values on 2026-11-07:

| Models | `maxTokens` (context) | `max_token_limit` |
|---|---|---|
| gemini-3.8-flash-*, gemini-4-argon-* | 1,048,576 | 256000 |
| claude-*-5-5-* | 1,000,000 | 256000 (840000 only under the `/claude-1m_840k` variant key) |
| gpt-oss-120b-medium | 131k | 80000 |

All of them have `token_threshold` 50000, `enabled` true, `max_user_requests` 10 and `include_last_user_message` true.

**Live probe** (`scripts/probe-compaction.mts`, gpt-oss)
- After a call whose context reached ~82.5k (> 80k), the next prompt first wrote a CHECKPOINT step (step_type 23).
- The following call's context dropped to ~36k.
- User messages survived; older tool outputs and reasoning were dropped.

**Conclusion:** agy compacts a warm ACP session at `max_token_limit` (≈256k for Gemini/Claude). That is far below the 1M windows realagy used to advertise to pi.

**Manual / override controls**
- The CLI has `/compact` (shared.ParseCompactRequest, prehooks.manualCompactionRequested). ACP also exposes the `/compact` slash command in `available_commands_update`.
- `AGY_CLI_AUTO_COMPACT_OVERRIDE` takes "N" tokens or "P%" (1–100) of the context window and cannot disable compaction.
- It is read only in cli/store (Store.ContextWindow → Manager.syncContextWindow, TUI model selector).
- Verified: `AGY_CLI_AUTO_COMPACT_OVERRIDE=20000` had no effect on `agy acp`; Gemini reached 77k with no checkpoint.

**Other agy "memory"**
- `~/.gemini/antigravity-cli/knowledge/` (Knowledge Items) was empty here.
- `implicit/` and `annotations/` hold only titles.
- `conversation_summaries.db` is the FTS conversation index.
- `~/.gemini/GEMINI.md` is injected as global rules.

**Tooling**
- Function addresses come from parsing the Go pclntab (magic f1ffffff 00 00 01 08, text base 0x140001000) with capstone.
- Scripts are in /tmp/agystr (pcln.py, agydis.py, callers.py).
