Verified on real agy 1.5.3 conversation DBs, including pi-qbot (2026-11-09). User images are repeated `19.9` entries `{1: mime, 5: uploaded path (.user_uploaded/...), 2: bytes}`; `19.2` and mirror `19.3.1` are text only. Image-only prompts use `See the attached images.` (`IMAGE_ONLY_PROMPT` in `src/transcript.ts`); the older `19.3.2` fixture assumption was wrong. Pi-bridge tool images are repeated `140.2.4` entries `{1: mime, 5: file uri, 2: bytes}`. `140.2.1` contains pi text plus `\n[Resource offloaded to <file uri>]` per image, or only those lines when there is no text. Mirror `140.2.3` (also copied in `render_info`) has `5: "Executed"` and repeated `10` parts: an Arguments/Result text block, then `{2: {1: uri, 2: mime, 3: tool}}` per image. In `src/acp/trajectory-sync.ts`, `nativeToolResult`, `rewriteToolRender`, and proto helpers `repeatedProtoBytesAt`/`rewriteRepeatedProtoFields` drop all copies, retain media when only text changes, and fail closed if URIs disagree across offload lines, mirror, and media. realctx user-image placeholders are separate text blocks: `[#N dropped · user image · …]` or `[#N dropped · 2 user images · …]`; `REALCTX_USER_IMAGE_DROP` must allow the count. A custom-agent/provider MCP `history` result may also appear in `gen_metadata.data`; an assistant response may separately repeat it.

Error MCP results (`isError`) are stored with step status 7 and no `140.2.1`: text is at payload `31.2`, mirror `31.3`, and `steps.error_details` column fields 2 and 3, all byte-identical to pi's `formatToolResult` text. Render mirror `140.2.3` holds only arguments (no **Result** section). The model sees `Encountered error in tool execution: <text>`. A `parallel` batch is one native 15 planner plus one 132 step `mcp_pi-bridge_parallel`, with text exactly `formatParallelResults` JSON (`JSON.stringify(...,null,2)`); pi has one assistant with N toolCalls ids `<batchUuid>:k` and N toolResults. If any entry isError, the whole step is stored as error (status 7). Bridge-local rejections (`extensions/index.ts` “Pi tool X is not active in pi right now. Active pi tools: …”, `parallelErrorResult`) create native planner+error steps pi never sees. Mid-turn steering is appended to the last result's text as `\n\n<pi-steering>\nThe user sent a steering message while this tool was running. Address it immediately:\n…\n</pi-steering>`; pi keeps steering as a separate user message after the toolResults, with no native user step. Bridge callIds are random UUIDs (`src/mcp-server.ts`), not linked to native call ids (`5.4.1` `call_…`).
