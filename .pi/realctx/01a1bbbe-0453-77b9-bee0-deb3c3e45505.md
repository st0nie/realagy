Verified on real agy 1.5.3 conversation DBs. User images are repeated `19.9` entries `{1: mime, 5: uploaded path (.user_uploaded/...), 2: bytes}`; `19.2` and mirror `19.3.1` are text only. Image-only prompts use `See the attached images.` (`IMAGE_ONLY_PROMPT` in `src/transcript.ts`); the older `19.3.2` fixture assumption was wrong. Pi-bridge tool images are repeated `140.2.4` entries `{1: mime, 5: file uri, 2: bytes}`. `140.2.1` contains pi text plus `\n[Resource offloaded to <file uri>]` per image, or only those lines when there is no text. Mirror `140.2.3` (also copied in `render_info`) has `5: "Executed"` and repeated `10` parts: an Arguments/Result text block, then `{2: {1: uri, 2: mime, 3: tool}}` per image. In `src/acp/trajectory-sync.ts`, `nativeToolResult`, `rewriteToolRender`, and proto helpers `repeatedProtoBytesAt`/`rewriteRepeatedProtoFields` drop all copies, retain media when only text changes, and fail closed if URIs disagree across offload lines, mirror, and media. realctx user-image placeholders are separate text blocks: `[#N dropped · user image · …]` or `[#N dropped · 2 user images · …]`; `REALCTX_USER_IMAGE_DROP` must allow the count. A custom-agent/provider MCP `history` result may also appear in `gen_metadata.data`; an assistant response may separately repeat it.
